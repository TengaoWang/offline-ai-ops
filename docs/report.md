## 1. 一句话总结

现场人员在本机和本地 AI（qwen3:8b）对话，或在界面上点「一键体检」，系统就会按技能包**在本机执行白名单只读命令** → **规则树逐层判定** → **规则没覆盖的交给 AI** → 输出带**手册真实页码**的分级报告，并记住现场信息和以前的排查经历。全程离线。

## 2. 完成情况

| 需求 | 实现 | 验证 |
|---|---|---|
| FR-2 技能库 | 4 个交换机技能（网络连通、Flash 存储空间、SSH 登录、日志审计）；新建目录自动识别，格式错误的标出原因 | 单元测试 |
| FR-3 一键采集 | 本机命令真实执行（Windows：`ping -n`、`ipconfig`；macOS：`ping -c`、`ifconfig`、`netstat -rn`）；交换机命令读手册示例回放；单条 10 秒、总共 30 秒时限 | macOS 真机执行；单元测试 |
| FR-4 规则树 | YAML 决策树：命令输出 → 中间结论 → 根因，界面显示每步命中哪条规则、走向哪个分支 | 同一棵树用两份输出走出不同路径（单元测试） |
| FR-5 混合判定 | 规则树负责确定性判断；规则没覆盖的日志交给模型推理，标注「AI 推理」，出处由程序检索后让模型选编号 | 日志审计：MSTP TC 报文由 AI 判断，引用手册 21.8.1.3 |
| FR-6 分级报告 | 🔴 严重 / 🟡 警告 / 🟢 正常，每条有现象、根因、修复命令（写操作只建议，不执行） | 每个技能至少 3 条（单元测试） |
| FR-7 强制溯源 | 技能里只写章节号，`llm.cite()` 从手册索引查真实页码和原文；查不到就显示「手册中未找到依据」 | 所有技能引用的章节号都能在手册中找到（单元测试） |
| FR-8 沉淀技能 | 一次排查存成新技能目录（含回放数据），可以直接执行；AI 的结论转成规则并标注「待人工确认」 | 保存后再执行，结论一致（单元测试 + 界面接口实测） |
| FR-9 白名单 | 危险字符 → 拆分参数 → 白名单 → 不经过 shell 执行；`ping 1.1.1.1; rm -rf /` 等 9 种注入、越界参数、交换机写命令全部拒绝 | 单元测试 |
| 对话里排查 | `python -m llm answer` 里说「帮我查一下」就执行技能；只描述现象时先查手册回答，再问「要我现场排查吗？」 | 真实模型实测 |
| 长期记忆 | 记住现场信息（如「MES 服务器是 192.168.10.20」）和每次排查记录；下次自动取地址、并能说出「和上次一样」 | 真实模型实测；单元测试 |

## 3. 架构

```
现场人员 ── 界面一键体检（ui/，Haward）──┐
        └─ 命令行对话 python -m llm answer ──┤
                                             ▼
llm/  qa.py 调度器（打招呼 / 超范围 / 追问 / 查手册 / 排查 / 记住）
      memory.py 长期记忆（SQLite 检索 + 每条一个 Markdown 文件，可直接改）
      diagnose.py 选技能 → 执行 → 模型结合以前的记录写总结 → 写入记忆
                                             ▼
engine/ skill_engine.py（界面用的 SkillEngine 接口）
        executor.py 白名单执行 → rules.py 规则树 → judge.py AI 补充 → runner.py 报告 → skillgen.py 存技能
                                             ▼
llm/  cite.py 章节号 → 真实页码；rag.py 手册混合检索（BM25 + bge-m3）
      Ollama / llama.cpp（qwen3:8b、bge-m3），全部本机
```

模型只负责**选技能、写总结、补充推理**；执行什么命令、怎么判定、出处在哪，都由程序决定，防止小模型乱执行命令或编造页码。

## 5. 演示流程（场景 A）

```text
你：记一下：MES 服务器的业务地址是 192.168.10.20，接在交换机 GE0/0/8，应该属于 VLAN 10
你：MES 服务器连不上了，帮我查一下
  → 本机真实执行：电脑有 IP ✓ → 网关能通 ✓ → MES 不通 ✓
  → 交换机（回放）：端口 up → PVID 是 1，不是 VLAN 10
  → 🔴 端口 GE0/0/8 的 VLAN 划分错误
     建议：system-view → interface GigabitEthernet0/0/8 → port link-type access → port default vlan 10
     出处：《华为S系列园区交换机维护宝典》22.53.3.2 VLAN的划分 P2454
你：MES 那台又连不上了，帮我排查一下
  → 「本次问题与 10月04日 那次一样……」
```

演示前检查和现场网络不对时的处理见 [`usage.md`](usage.md) 第 7 节。

## 6. 和 Haward 的合并

`main` 上 Haward 的 `cea93c6` 也实现了引擎和技能并接入界面。按团队决定**以本方案的引擎和技能为准，界面适配**：

- 新增 `engine/skill_engine.py` 适配层，接口和原来的 `SkillEngine` 一致，**`ui/` 没有改动**。
- 保留 Haward 的 `ui/`、llama.cpp 后端、索引快照、英文问答、打包脚本、评测和界面测试。
- 替换了他的引擎（`executor.py`、`rules.py`、`skill_loader.py`）和 4 个技能内容，删除 `saved-7ce098e844d8` 和旧的 `saved-skill-1791027243`。
- 对话里排查和长期记忆默认关闭（`answer(..., diagnose=True)` 才打开），界面问答行为不变。

**待对齐**：Haward 的 `eval/eval_p0_diagnostics.py` 要求「每条结论都有出处，否则不发布」；本方案是照常显示并标「手册中未找到依据」（FR-7），因此该评测有 2 项不通过。

## 7. 如实说明（答辩时可能被问到）

| 问题 | 说明 |
|---|---|
| 交换机输出是真的吗 | 没有真实交换机。交换机命令的输出取自手册示例，为演示场景改过个别字段（例如加了 GE0/0/8、PVID 设为 1），每份回放文件第一行写明出自哪一页、改了什么 |
| 本机命令为什么有的结论没出处 | `ping`、`ipconfig` 是电脑系统命令，华为手册里没有，如实显示「手册中未找到依据」 |
| 阈值从哪来 | 「Flash 使用率超过 90%」是经验值，手册只要求空间充足；VTY 默认 5 个来自手册 19.3.4 |
| AI 推理可靠吗 | 只用在规则没覆盖的日志上，标注「AI 推理」；它给出的修复命令没有逐条核对手册 |
| 修复命令会自动执行吗 | 不会。只执行白名单只读命令，修改配置的命令只在报告里作为建议 |

## 8. 已知问题和下一步

1. **Windows 真机验证**（最优先）：跑一遍单元测试和 `python -m engine run net-unreachable --no-ai`。
2. 和 Haward 统一「无出处结论」的处理方式。
3. 调度器的两处回归（应追问的笼统问题）。
4. 记忆检索相关度门槛偏宽；同一问题多次排查会重复记录，可以合并成一条并记下次数。
5. 只说「一键体检」时会随便选一个技能，应让用户选择。
6. 界面问答框可选接入 `diagnose=True`（说明见 [`frontend-answer.md`](frontend-answer.md) 第 11 节）。
