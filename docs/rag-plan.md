## 1. 总体流程

```
【建索引：离线做一次，约 20 分钟】
手册 PDF ─→ ① 解析 ─→ ② 切块 ─→ ③ 建索引 ─→ kb/index.db（约 50MB，可直接拷贝）
            去目录页      按章节切       BM25 关键词索引
            去页眉页脚    ≤600 字/段     + bge-m3 向量

【检索：retrieve()，约 0.06 秒，Agent 每轮直接调用】
问题 ─→ ④ 双路召回 ─→ ⑤ 合并排序 ─→ 前 k 段（带出处）
         BM25 前 20     RRF 合并
         向量前 20      同一小节只留一段

【问答：ask()，15 到 50 秒】
前 5 段 ─→ ⑥ 补上下文 ─→ ⑦ 模型回答 ─→ ⑧ 出处保护 ─→ 回答 + 出处
            补相邻段       Qwen3-8B         编号换成真实出处
            合并成 3 段    JSON 格式输出    检查命令；没依据就拒答
```

## 2. 各环节的做法和理由

| 环节 | 做法 | 为什么 |
|---|---|---|
| **① 解析** | PyMuPDF 逐页提取文字；点号占比超过 30% 的页当作目录页跳过；每页最后 6 行中，在多页重复出现的行、纯数字页码、一级章名当作页眉页脚删掉 | 目录页会挤占检索结果；页眉页脚是噪音 |
| **② 切块** | 按 PDF 书签找到每个小节标题所在的行，从标题行切开（3099 个书签中 3098 个找到了标题行）；每节再切成不超过 600 字的段，只在行与行之间切，相邻段重叠约 100 字；只有一行标题的小节不单独成段。共 7091 段，平均 463 字 | 按页切会把章节标错（22.28 的内容被标成 22.29）；只在行之间切，命令不会被切断 |
| **③ 索引** | 一个 SQLite 文件里放两部分：<br>• **BM25**：jieba 分词 + FTS5，标题字段放完整章节路径（含章名）<br>• **向量**：bge-m3 通过 Ollama 计算（1024 维，归一化后存储），算向量时把章节名放在正文前面 | 全部在一个文件里，随 SSD 带走；不需要向量数据库，7000 多段直接用 numpy 计算相似度就够快 |
| **④ 召回** | 关键词前 20 + 向量前 20 | 关键词擅长精确的命令和接口名（`GE0/0/1`、`trunk`）；向量擅长口语和同义说法。两者互补 |
| **⑤ 合并** | 加权 RRF：关键词这一路排第 r 名得 1/(60+r) 分，向量这一路得 2/(60+r) 分，两路相加（权重在测试集上 1.5 到 3 结果相同，取中间值 2）；同一小节只保留分数最高的一段；没有向量模型时自动只用 BM25 | 只看名次不看原始分数，稳定；向量加权后口语题明显提升，命令类题不受影响；去重避免前几名被同一节占满；有向量模型时能用，没有时也能退回 BM25 |
| **⑥ 补上下文** | 每个命中段补上同一小节的前后各 1 段，连在一起的合并，重叠行只保留一次，最多给模型 3 段 | 一个配置示例常被切成好几段，只命中「查看结果」那一段时，模型看不到配置命令 |
| **⑦ 回答** | Qwen3-8B 本地运行，关闭思考模式，温度为 0，用 JSON Schema 限定输出 `{found, answer, citations}`；提示词规定只能用资料里的内容、命令必须原样照抄、名字相近的功能不能混用 | 格式稳定；结果可以复现；减少编造 |
| **⑧ 出处保护** | ① 模型只填资料编号，由程序换成真实的文件、章节、页码<br>② 编号不存在就丢掉，没有有效出处就拒答<br>③ 回答里的每条命令都要能在出处原文里找到（忽略数字，设备输出不算命令）；在别的资料里找到就修正出处，都找不到就拒答 | 出处不会被编造；拼凑或编造的命令会被拦下 |

## 3. 接口（队友调用）

| 接口 | 返回 | 说明 |
|---|---|---|
| `retrieve(query, k=5, mode=None)` | `[{id, text, file, page, section, label, score, vec_score, bm25_rank, vec_rank, mode}]` | 按 `score` 从高到低排。Agent 循环里用它查手册，`label` 可直接作为出处 |
| `ask(question, k=5)` | `{answer, found, citations, unsupported_commands, latency_s}` | 带出处的问答；`found` 为 False 时 `answer` 固定为「手册中未找到依据。」 |
| `python -m llm search / ask "问题"` | 给人看的格式 | 加 `--json` 输出原始数据 |
| `python -m llm ingest` / `embed` | — | 重建索引 / 只补算向量 |

配置（环境变量）：`LLM_EMBED_MODEL`（默认 `bge-m3`，设为空则只用 BM25）、`LLM_RETRIEVE_MODE`（`hybrid` / `vector` / `bm25`）。

## 5. 改进过程的数据

| 版本 | Hit@1 | Hit@3 | 口语题 Hit@3 | 出处章节 |
|---|---|---|---|---|
| 起点：只用 BM25，按页切 | 73% | 80% | 60% | 有错 |
| + 向量混合检索 | 80% | 90% | 80% | 有错 |
| + 按章节切、去页眉页脚 | 70% | 90% | 80% | **正确** |
| + 补相邻段、命令检查、去重 | 73% | 90% | 80% | 正确 |
| + 向量权重 ×2（**当前**，测试集 31 题） | 77% | 94% | 91% | 正确 |

- FR-2 的 5 道预设题全部排进前 3。
- 手册里没有的问题能正确拒答（Windows、MySQL、AR2200、Linux 都测过）。
- 检索耗时约 0.06 秒；问答 15 到 50 秒，**还没有达到「每轮不超过 30 秒」**。
- 建一次 bge-m3 向量约 20 分钟（MacBook Air M4）。

## 6. 还没做的

| 优先级 | 内容 |
|---|---|
| 高 | **提速**：问答压到 30 秒以内（截短资料、限制回答长度、模型常驻内存） |
| 高 | **拒答阈值**：手册里没有的问题在检索阶段就拦下来；只有关键词命中、没有向量支持的结果降权 |
| 高 | **端到端评测**：检查回答里是否包含正确的命令，统计误拒率 |
| 中 | 去掉问句里的虚词（「是不是」被当成关键词，带来噪音） |
| 低 | 向量缓存、文字建议的核对、问句停用词 |

## 7. 一句话概括

> 用 BM25 加 bge-m3 做混合检索，按章节切块保证出处准确；问答时补全上下文，由程序把编号映射成出处，并逐条核对命令，做到「答必有据、无据就拒」；全部本地离线运行，用测试集量化每一步改进，口语题命中率从 60% 提到 91%。
