## 1. 定位与目标

前端是「离线运维助手的操作台」，承担四个角色：

1. **入口**：选技能包 / 描述故障 → 触发诊断。
2. **过程可视化**：采集命令逐条执行、规则树判定路径可展开、AI 补充推理可见。
3. **结果呈现**：分级故障报告 + 修复指令 + 手册强制溯源。
4. **知识沉淀**：一键「存为技能」，新技能出现在列表并可复用。

交互主线（来自需求文档 §4.2，演示固定走这条）：

```text
选技能包 → 一键采集 → 规则树判定（可展开路径）→ 报告（含手册出处）→（可选）存为技能
```

目标用户是**无运维背景的现场人员**，因此界面必须零学习成本、主线一键走完（需求文档 §1.3）。

## 2. 范围

### 2.1 本次做（In Scope）

- 技能包列表与选择、故障描述自动路由。
- 采集过程流式展示（命令 + 原始输出 + 状态 + 耗时）。
- 规则树判定路径可视化（可展开）。
- 分级故障报告 + 修复指令 + 手册溯源展示。
- 知识问答（带溯源）页面，作为现场保底演示。
- 手册导入与建索引入口（拖拽/选择文件、重建索引、展示解析结果）。
- 「存为技能」入口与草稿预览。
- Evidence 对比面板（手动 vs AI 的耗时、步骤数、溯源可信度对比）。
- 系统状态（Ollama / 模型 / 索引）展示。
- 完全离线运行（本地资源打包、零 CDN、零外网请求）。

### 2.2 本次不做（Out of Scope）

- 开放 Agent 循环、自由工具调用（需求文档架构决策 #1 已排除）。
- 写操作自动执行（安全红线，只展示建议指令）。
- 多设备/多手册管理界面（可后续扩展）。
- 账号、权限、审计等企业级功能。

## 3. 设计原则

1. **离线优先**：所有资源本地打包，禁止任何 CDN / 外网请求；前端与后端通信只走本机回环 `127.0.0.1`。
2. **过程感优先**：命令执行、模型推理必须流式回显，不做「转圈 → 一次性出结果」。
3. **溯源可信**：页码/章节由后端元数据给到前端，前端只负责排版渲染，**不参与出处生成**。
4. **诚实降级**：无依据、命令失败、超时都要显式呈现，不伪造结论。
5. **安全边界可见**：「建议执行」的写操作要有醒目警示，与「自动执行」的只读命令在视觉上严格区分。

| 页面 | 作用 | 对应需求 |
| --- | --- | --- |
| 首页 / 诊断台 | 技能选择 + 故障描述路由 + 一键体检 | FR-2、FR-3 |
| 采集过程 | 逐条命令与输出、状态、耗时、拦截提示 | FR-3、FR-9、FR-12 |
| 判定路径 | 规则树命中路径 + AI 补充推理 | FR-4、FR-5 |
| 诊断报告 | 分级清单 + 修复指令 + 溯源 + 存为技能 | FR-6、FR-7、FR-8 |
| 知识问答 | 手册带溯源问答（保底） | 场景 C |
| 手册导入 / 索引 | 上传设备手册、重建索引、展示页码/章节解析结果 | FR-7 补充 |

| 系统状态 | 健康检查与就绪引导 | health() |

### 4.2 各页面字段与交互

#### 首页 / 诊断台

- 技能包卡片列表：名称、简介、包含检查命令数。
- 两个入口：
  - 点选技能包直接进入诊断。
  - 输入故障描述 → 技能选择为可选项；未指定技能时调用 `route()` 自动选择，返回 `null` 时提示「不属于任何技能包，转人工」。
- 【一键体检】直接运行当前明确选中的技能，不要求再输入故障描述；【开始排查】提交现场描述，可自动路由或使用手动指定的技能。未选择技能时一键体检不可用，开始排查保持可用。
- 技能包列表**自动识别** `skills/` 目录，新增目录无需改前端代码即出现新技能。
- 技能库提供搜索与过滤，避免技能增加后卡片无限堆叠；技能选择器支持“不指定技能，自动匹配”。
- 最近对话显示在左侧导航栏，支持新建后切换、重命名和删除；每个会话单独保留聊天流、诊断状态与出处。聊天流在页面容器内滚动，输入区保持可见。
- 首次提问后生成概括问题的会话标题；模型可用且非 Mock 时由本地模型生成，Mock/模型不可用时使用本地场景摘要。标题可手动改名。
- 三个现场问题入口是预置场景提示。点击后仅填入故障描述输入框，允许修改，用户需再点击【开始排查】才会提交。当前 `/api/diagnose/stream` 由 `DEMO_RUNS` 固定演示数据提供，不受模型健康状态影响；本机模型可用仅代表标题/路由等模型能力可用，不表示诊断采集、判定和报告引擎已接入。接入真实诊断引擎后，前端再展示其返回的实时结果，不将固定样例标为实时推理。
- 提供中文/英文界面切换。切换界面语言不改写用户提交的问题、命令回显或原始手册片段。

#### 采集过程

- 每条命令展示：命令文本、原始输出、状态（成功/失败/超时/被拒）、耗时。
- 流式/实时回显，逐条推进。
- 白名单拦截时明确提示：「该命令不在白名单，已拒绝」。
- 命令失败/超时不中断流程，该项标注「未能获取」及原因。

#### 判定路径

- 规则树逐层展开，显示命中/未命中与走向分支。
- 判定来源标签：`规则树判定`（确定性）/ `AI 补充推理`。
- 规则未覆盖时显示「AI 补充判定」；仍无法判定进 `unresolved`，诚实展示。

#### 诊断报告

- 分级清单：🔴 严重 / 🟡 警告 / 🟢 正常。
- 每条含三要素：现象 / 根因 / 修复指令。
- 修复指令（写操作）以「建议执行」呈现，附安全提示：「本 AI 仅给出指令建议，不自动执行；操作前请备份配置」。
- 每条结论展示《手册名》§章节 P页码，可点击查看原文片段。
- 无依据时显示「手册中未找到依据」。
- 【存为技能】按钮 → 草稿预览 → 确认保存 → 新技能出现在列表。

#### 知识问答

- 输入问题 → 返回带出处的答案。
- 展示 `citations` 的 `label`（《手册》章节 P页码）与原文片段。
- 无依据时明确显示「手册中未找到依据」。

#### 手册导入 / 索引

- 支持拖拽或选择 PDF / Markdown / TXT 设备手册，文件只保存到本地知识库目录。
- 点击【重建索引】后展示进度与结果：文件数、片段数、页码/章节解析样例。
- 建索引失败时显示失败原因，并保留「使用预置手册继续演示」的降级提示。
- 索引未就绪时，知识问答和报告溯源入口显示「索引未就绪」，不展示伪造出处。
- 解析结果中抽样展示 3 条片段，包含文件名、章节、页码，便于人工核对溯源质量。

#### Evidence 对比

- 手动排障记录：耗时、步骤数、翻手册次数、备注。
- AI 排障记录：从一次诊断运行中自动读取耗时、采集命令数、报告条目数、出处条数。
- 自动生成对比表：步骤数、耗时、判读可靠性、知识可信度、知识沉淀、成本、诚实边界。
- 支持复制/导出 Markdown 对比表，用于答辩材料和备份演示。
- Evidence 数据只保存在本地，不上传外部服务。

#### 系统状态

- 展示 Ollama / 模型 / 索引 / 片段数 就绪状态。
- 未就绪时给出下一步操作提示（启动 Ollama、下载模型、建索引）。
- 模型加载状态展示（「模型加载中，约 ≤3 分钟」）。
- 展示当前 Mock 诊断模式，并提供不连接真实设备的交换机固定样例模拟台。
- 标明 U 盘启动脚本与 Ollama / llama.cpp 双方案打包状态；原型阶段明确显示该发布能力尚未交付。
- 【刷新系统状态】触发 `GET /api/health`，显示刷新中、成功时间或错误信息。

## 6. 架构与关键决策

### 6.1 前端与后端关系

- 后端：`llm/`（现有）+ `engine/`（待建）+ 新增本地服务层（HTTP + 流式）。
- 前端：消费后端接口，自身为纯静态资源，由本地服务一并提供（避免 `file://` 跨域失败）。
- CLI 与前端共用同一后端内核，保证行为一致。

前端联调接口（均由本机服务提供）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 刷新系统、模型、技能与索引状态 |
| GET | `/api/skills` | 发现技能包并返回搜索展示字段 |
| POST | `/api/route` | 根据故障描述自动匹配技能 |
| POST | `/api/title` | 使用本机模型生成会话摘要标题；Mock/模型不可用时返回本地摘要 |
| GET | `/api/diagnose/stream?skill=…` | 通过 SSE 返回采集、规则、推理和报告事件 |
| POST | `/api/ask` | 检索本地手册并返回带出处的答案 |
| GET | `/api/manuals/samples` | 返回本地索引的解析样例 |
| POST | `/api/manuals/upload`, `/api/manuals/ingest` | 导入手册并重建索引 |
| POST | `/api/save-skill` | 保存可复用技能草稿 |

### 6.2 客户端形态（选型待评审）

| 方案 | 优点 | 缺点 | 适配度 |
| --- | --- | --- | --- |
| 本地 Web + 系统默认浏览器 | 零壳依赖、最稳、最省体积 | 非独立窗口 | 1.0 首选 |
| pywebview | 观感接近独立客户端、全 Python | 依赖系统 WebView | 平衡之选 |
| Tauri | 体积小、观感好 | 引入 Rust 工具链 | 产品化再上 |
| Electron | 渲染一致 | 体积大、与轻量便携冲突 | 不推荐 |
| Gradio | 最快 | 观感非「类 Claude Code」 | 兜底 |

### 6.3 流式方案

- 聊天/问答/采集采用 SSE（Server-Sent Events）或 WebSocket，实现打字机效果。
- 需要后端 `client.chat()` 支持 `stream=True` 并输出分片。

### 6.4 离线打包方案

- 前端：构建产物（dist）本地打包，零 CDN。
- 后端：PyInstaller 单文件（Windows `.exe` / macOS `.app`），目标机免安装 Python。
- 服务：只绑定 `127.0.0.1`，前端由后端静态托管。

## 9. 验收标准

- 断网 + 关 WiFi 后，场景 A/B 全流程通过（FR-1）。
- 4 个技能包均可一键执行，新增目录即自动识别（FR-2）。
- 采集逐条回显，30 秒内完成，拦截与失败清晰呈现（FR-3、FR-9、FR-12）。
- 规则树路径可展开，AI 推理来源显式标注（FR-4、FR-5）。
- 报告 ≥3 条分级项，每条含现象/根因/修复指令，出处页码与手册一致（FR-6、FR-7）。
- 存为技能后新技能出现在列表并可再次执行（FR-8）。
- 无依据时显示「手册中未找到依据」，不编造出处（FR-7）。
- 上传/导入一份手册后可重建本地索引，并展示文件数、片段数、页码/章节抽样（FR-7 补充）。
- 产出手动 vs AI 对比表，至少包含耗时、步骤数、翻手册次数、AI 自动执行命令数（FR-11）。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 流式通道未打通导致体验不达标 | M1 即冻结流式方案并打通最小闭环 |
| 离线打包遗漏 CDN/运行时依赖 | 打包脚本固化 + 断网冒烟测试 |

| 溯源展示参与页码生成导致失真 | 前端只消费后端元数据，禁止自行拼页码 |
| 目标机精简系统缺 WebView | 1.0 用系统默认浏览器，避免 WebView 依赖 |
| 手册解析页码/章节质量不稳 | 手册导入页展示抽样片段和解析告警，支持回退到预置手册 |
| Evidence 数据现场忘记记录 | 前端提供计时/步骤输入和诊断结果自动填充，结束时一键生成对比表 |
